[00:58] Luke Meyer: In project1_model.py, the base inputs start with Cadence's FY2025 opening financials and explicit forecast assumptions. The named downside, base, and upside cases use the same model structure. The forecast links revenue, gross profit, operating expenses, taxes, working capital, capital spending, depreciation, debt, equity, and cash. Cash is the balancing item, and the model separately checks both the balance sheet and cash-flow statement.

[01:35] Luke Meyer: The forecast then calculates FCFF and discounts it using the selected WACC. Terminal growth must remain below WACC. Enterprise value is bridged to equity value by adding cash, subtracting debt, and dividing by diluted shares. The committee decision function applies one disclosed rule to the calculated value: initiate only with a 15% margin of safety, watch and defer above the modeled downside floor, and do not initiate at or below that floor. A failed integrity check stops the decision.

[02:12] Luke Meyer: The newer functions extend that same core. The market-expectations dashboard solves for the revenue-growth shift, WACC, or gross margin required to reach the market price. The semiconductor regimes move operations and beta together. The Hexagon function values the acquisition as a separate incremental overlay, so the FY2025-based statements are not silently mixed with post-acquisition assumptions.

[02:43] Luke Meyer: App.py imports those functions and presents their outputs. It does not recreate the valuation logic. Changing a sidebar input sends a new input set through run_model, and the displayed action comes from the calculated result. This separation lets the same model drive the interface, the visible text output, and the tests.
